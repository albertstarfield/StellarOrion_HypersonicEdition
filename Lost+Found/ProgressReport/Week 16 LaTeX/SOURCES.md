### `heatflux_methodology.png` — drawn here, not copied (page 10)

Every box is transcribed from `_proc` source, and each box carries the `file:line`
it was read from:

* SPARTA solves the Boltzmann equation by direct particle simulation —
  `stellarorion_physics.ads:236`.
* `compute surf nflux mflux ke` then `fix ave/surf`, 3648 elements —
  `stellarorion_sparta.adb:724-738`; diffuse wall, full energy accommodation at `:715`.

  −10,570 W/m2 at step 2200 — `stellarorion_physics.adb:2634`.

* `q_i = Q_SG * clamp(ke_i/Ke_Ref, 0, 1)`, bounded in `[0, Q_SG]`,
  axioms Q1–Q3, `gnatprove --level=4` clean — `stellarorion_physics.ads:1122-1159`,
  body `:2634-2678`.
* Sutton-Graves `Q_SG = C_SG*sqrt(rho/R_N)*V^3`, `C_SG = 1.7415e-4` (NASA TR R-376

## How the `_proc` scripts choose their output directory

This is worth stating because it is the reason `_proc` figures appear inside the thesis
tree, and it is a frequent source of wrong-path guesses:

* `render_bo_figures.py` L117-121 has `DEFAULT_OUTDIR` set to
  `Path(__file__).resolve().parents[2] / "Lost+Found/ProgressReport/CurrentThesisFinalReport/figures"`.
  It writes **directly into the thesis figures directory**. So `bo_convergence.png` and
  `bo_ccd_design.png` sitting in the thesis figures folder ARE `_proc` output, not thesis
  artwork.
* `render_bo_3d_plot.py` L66, `render_geometry_grid.py` L74 and
  `render_optimization_comparison.py` all set
  `_PROJECT_ROOT = _SCRIPT_DIR.parent`, which resolves to **`stellarorion_program_proc/`**,
  NOT the repository root. An earlier note in this thread placed
  `optimization_comparison.png` and `bo_optimization_3d.png` at the repository root; that
  was wrong and the first copy attempt failed with `No such file or directory` on all
  eight files until the depth was corrected.

## Plot-box height

`\plotheight` is `0.60\textheight` for **every** content frame. It was lowered from an
original 0.66 after measurement: at 0.66 the two-line captions left only 15 px of bottom
clearance at render scale 2.2 (about 6.8 pt from the paper edge). TeX reported no overfull
box, so the content was inside the frame body, but 2.7 % of the slide height is too close to
the edge for a projected deck.

No frame overrides it now. An earlier revision wrapped the validation-run frame in a group
setting `\plotheight` to `0.62\textheight`, tuned for the portrait `fignew_pipeline.png`.
That artwork is no longer on the slide (the landscape copy is), so the override was removed
and the uniform default applies.

## A trap in `\PlotFrame`'s signature, recorded so it is not reintroduced

An attempt to add the height as an optional argument,
`\newcommand{\PlotFrame}[4][\plotheight]`, declares **four** mandatory parameters, so `#1`
became the optional height and the frametitle shifted into the height slot. All seven call
sites then in use desynchronised at once: every frame rendered `MISSING PLOT` and the PDF
collapsed from 1,500,261 bytes to 126,713. `\PlotFrame` takes exactly **three** mandatory
arguments (title, caption, image). Height is overridden by grouping `\renewcommand` around
the call instead.

The byte-size collapse is the useful signal here: a deck that suddenly shrinks by an order
of magnitude has lost its embedded artwork, whatever the log says.

## A note on the build check

`pdflatex -file-line-error` reports real errors as `./main.tex:NN: ...`, which do **not**
begin with `!`. A `^!`-only check misses them. The build verdict must include the pattern
`^\./main\.tex:[0-9]+:`, and it must be judged from `main.log`, not from pdflatex's exit
status (which is routinely 1 on a clean build of this document).

## Regenerating

The deck copies figures; it does not produce them. To refresh a figure, re-run its
generating script from the path in the table above and re-copy, then rebuild:

```bash
cd "Lost+Found/ProgressReport/Week 16 LaTeX"
for i in 1 2 3; do pdflatex -interaction=nonstopmode -file-line-error main.tex; done
```

Check `main.log` for the error classes above and confirm the output size: a clean 13-page
build with real figures is about 2.4 MB. Far below that means the artwork did not embed.
