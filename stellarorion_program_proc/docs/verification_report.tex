\begin{abstract}
\noindent This report records the machine-checked and audit-based verification
layers of the StellarOrion HypersonicEdition project: the layered pipeline
gates (build, GNATprove, gnatcov, the Coq \texttt{coqc} gate, the static
sabotage audit, and the static link), the Coq/Rocq proof corpus of 79 proof
files with 267 proof obligations, and an honest account of what each layer
does and does not prove. Every theorem statement quoted here is transcribed
verbatim from its source file with file and line numbers; the per-file
status table in Section~\ref{sec:status} is generated mechanically from the
corpus and the pipeline gate's JSON output.
\end{abstract}

\section{Introduction and Scope}\label{sec:intro}

The project's verification story has three legs: (i) Coq/Rocq proofs of the
mathematical properties of the physics, geometry, optimization, and
FFI-marshalling routines; (ii) GNATprove proofs and flow analysis over the
Ada/SPARK simulation engine, which remains the dominant implementation
language; and (iii) a static sabotage audit of the whole codebase. This
document reports the state of leg (i) in detail, places it in the pipeline
of legs (ii) and (iii), and states the residual risk without decoration.

The proof corpus at the time of writing comprises 79 \texttt{.v} files:
28 under \texttt{proofs/}, 49 under \texttt{src/proofs/}, and 2 under
\texttt{src/rocq/}. The generated census in Section~\ref{sec:status}
counts 267 proof obligations (Lemma/Theorem declarations), of which 44 are
transparent placeholders whose statement is the literal \texttt{True}, and
15 sit in the two \texttt{src/rocq/} skeleton files whose proofs terminate
in \texttt{Admitted}. The proofs are developed against Coq/Rocq 8.18.0;
the version is recorded in the headers of the proof files themselves
(e.g.\ \texttt{proofs/hiad\_optimizer.v}, line 26).

\subsection*{Honesty rules applied throughout}

\begin{itemize}
\item A theorem is quoted only from a file that was read; the source file
  and line range accompany every quotation.
\item Compile success is never reported as proof success (Axiom~A2 above).
\item Placeholders (\texttt{: True}) and \texttt{Admitted} bodies are
  disclosed, counted, and never folded into a headline pass rate.
\end{itemize}

\section{Verification Architecture}\label{sec:arch}

The project standard mandates the validation pipeline order in
\texttt{code-quality.md} (lines 3116--3122)\footnote{Source of truth:
\path{~/.config/opencode/context/core/standards/code-quality.md},
section ``\texttt{run.py} MUST Wire Sabotage Verifier''.}:

\begin{quote}
\verb|1. alr build| $\to$ zero errors, zero warnings;\\
\verb|2. alr exec -- gnatprove --level=4 -j0| $\to$ all checks proved;\\
\verb|3. alr exec -- gnatcov --no-subprojects| $\to$ coverage meets threshold;\\
\verb|4. python src/utils/sabotage_verifier.py| $\to$ sabotage audit;\\
\verb|5. alr exec -- gprbuild -largs -static| $\to$ static binary.
\end{quote}

The Coq \texttt{coqc} gate belongs between step 3 and step 4: after the
SPARK proofs and coverage exist, and before the audit that would otherwise
treat a broken proof file as invisible. Table~\ref{tab:gates} states each
gate, the artifact it consumes, and what it discharges.

Two properties of the gate set matter for reading this report. First, the
sabotage verifier's Coq awareness is a \emph{static text check}
(\texttt{src/utils/sabotage\_verifier.py}, lines 6414--6471: it greps for
\texttt{Admitted.} and \texttt{Axiom} in \texttt{.v} files); it never runs
\texttt{coqc}. A proof file that is syntactically broken therefore passes
the audit and only the \texttt{coqc} gate catches it. Second, the mandated
failure semantics are fatal-and-uncatchable: per \texttt{code-quality.md}
lines 3166--3170, a verifier failure must print the violations, exit 1, and
continue neither silently nor via caught exceptions; the same discipline
applies to the \texttt{coqc} gate.

\begin{theorem}[Cross-section point count]\label{thm:hiad-count}
\texttt{Theorem cross\_section\_point\_count\_closed\_form :}
\texttt{forall npts\_per\_segment : nat, 2 <= npts\_per\_segment ->}
\texttt{cross\_section\_point\_count npts\_per\_segment = 4 * npts\_per\_segment - 3.}

\begin{proof}
\verb|intros npts_per_segment Hge. unfold cross_section_point_count. lia.|
(\texttt{proofs/hiad\_geometry.v}, lines 26--30): segment 1 contributes
$n$, segments 2--4 contribute $n-1$ each, so $n + 3(n-1) = 4n - 3$.
\end{proof}

\begin{theorem}[Segment containment]\label{thm:seg2}
\texttt{Lemma segment2\_contained : forall r\_tang r\_target t : R,}
\texttt{r\_tang <= r\_target -> 0 <= t -> t <= 1 ->}

\texttt{segment2\_radius r\_tang r\_target t <= r\_target.}
(\texttt{src/proofs/hiad\_geometry\_proof.v}, lines 82--85)
\end{theorem}
\begin{proof}
\verb|unfold segment2_radius. split| with \verb|Rmult_le_pos| and
\verb|Rmult_le_compat_r| on the offset term (lines 86--95).
\end{proof}

\section{Verification Coverage and Residual Risk}\label{sec:risk}

\subsection{What each layer actually checks}

\begin{description}
\item[Coq (this corpus)] checks the \emph{mathematical} content of each
\texttt{Definition} that models a unit: positivity, monotonicity, band
containment, index boundedness. It does not read the Ada or Python source;
the correspondence between a Coq model and the routine it mirrors is
established by transcription of the documented constants (the \texttt{.ads}
values, the Python literals) into the proof file, and is argued by
inspection, not machine-checked.
\item[GNATprove] checks the Ada/SPARK engine itself: run-time error freedom
and every Pre/Post contract at \texttt{--level=4}. This is the layer that
discharges the physical envelope axioms registered in
\texttt{docs/AXIOMS.md}; the documented gate command is
\texttt{scripts/prove.sh\ 4\ --report=all} (\texttt{docs/THEORIES.md}
records the last full run as 527 checks, 400 proved, 103 unproved, 24
flow-analysis checks, exit 0 --- quoted as documented, not re-measured
here).
\item[gnatcov] measures structural Ada coverage against a threshold.
Coverage is not correctness.
\item[The sabotage verifier] performs a static text audit. Its Coq-aware
checks (\texttt{src/utils/sabotage\_verifier.py}, lines 6414--6471 and
6738--6756) grep for \texttt{Admitted.}, \texttt{Axiom} and missing
\texttt{.v} files; a corpus verdict of CLEAN requires zero
CRITICAL+HIGH+MEDIUM findings. It never invokes \texttt{coqc}, so a
syntactically broken proof file would pass the audit.
\end{description}

\subsection{Residual risks, stated plainly}

\begin{enumerate}
\item \textbf{Model-to-code gap.} A proved Coq statement about a Definition
is not a proved statement about the compiled unit. No automation in this
repository closes that gap today.

\texttt{proofs/}, 33 under \texttt{src/proofs/}) have the literal statement
\texttt{Lemma X\_key\_property : True.} They are self-described in their

\section{Regenerating This Report}\label{sec:regen}

The status table and the theorem inventory between
\texttt{\% BEGIN GENERATED} and \texttt{\% END GENERATED} are produced by:

\begin{verbatim}
python3 scripts/gen_verification_report.py \
    --status results/coqc_status.json
\end{verbatim}

\noindent The script is Python-3 standard library only (no third-party
imports; no project virtualenv is required) and resolves the project root
from its own location, so it contains no hardcoded absolute paths. Options:
\texttt{--tex} (target document), \texttt{--status} (gate JSON),
\texttt{--strict} (fail on a malformed status file instead of degrading to
``not gated''), and \texttt{--dry-run} (print the fragment without
editing). Regeneration is idempotent: only the sentinel-delimited region
is rewritten, so hand-written prose is never clobbered.

\textbf{Status JSON contract.} The input is either a bare list of records
or an object holding such a list under \texttt{results}, \texttt{files},
or \texttt{coqc}. Each record is
\texttt{\{"path":\ "proofs/hiad\_geometry.v",\ "ok":\ true,\\
"error\_snippet":\ "..."\}}; paths may be repo-relative, project-prefixed,
or absolute, and are normalised internally. A missing or empty file yields
``not gated'' verdicts with a warning on stderr rather than a crash (the
opposite behaviour is available via \texttt{--strict}).
