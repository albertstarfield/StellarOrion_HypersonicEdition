### Key Observations:

1. **pdelta_force** is the change in momentum of the particle:
   - `pdelta_force = -origmass * vorig + imass * ip->v + jmass * jp->v`
   - This is `mass * (V_post - V_pre)` for the particle

2. **nfactor_inverse** = fnum/dt, so the force is:
   - `Fx = - Sum(pdelta_force_x) * fnum/dt`
   - Which is equivalent to: `Fx = - Sum(mass * delta_v_x) * fnum/dt`

3. **No area normalization** is applied to force — only `nfactor_inverse` (fnum/dt)

## From compute_surf.cpp — normflux Calculation (lines 203-222):

```cpp
// normflux for all surface elements, based on area and timestep size
// if normarea = 0, area is not included in flux
//   mass/eng fluxes (mass/area/time) becomes mass/eng flows (mass/time)
int axisymmetric = domain->axisymmetric;

for (int i = 0; i < maxsurf; i++) {
  if (!normarea) normflux[i] = 1.0;
  else if (dim == 3) normflux[i] = surf->tri_size(i,tmp);
  else if (axisymmetric) normflux[i] = surf->axi_line_size(i);
  else normflux[i] = surf->line_size(i);
}
```

### Key Observations:

1. **normflux** is only used for FLUX quantities (nflux, mflux, ke, etc.)
2. For 3D: `normflux = tri_size` (area of triangle)
3. For 2D axisymmetric: `normflux = axi_line_size` (surface area of revolution)
4. For 2D non-axisymmetric: `normflux = line_size` (length of line segment)
5. **Force (FX, FY, FZ) does NOT use normflux** — it only uses `nfactor_inverse`

## From surf.cpp — axi_line_size Function:

```cpp
double Surf::axi_line_size(int m)
{
  return axi_line_size(lines[m].p1, lines[m].p2);
}

double Surf::axi_line_size(Line *line)
{
  return axi_line_size(line->p1, line->p2);
}
```

The `axi_line_size` function computes the surface area of revolution of a line segment around the y-axis (the axis of symmetry in SPARTA's 2D axisymmetric mode).

For a line segment from (x1, y1) to (x2, y2):
- The surface area of revolution is: `π * (x1 + x2) * sqrt((x2-x1)² + (y2-y1)²)`
- This is the area of the frustum surface generated by revolving the line segment

## Conclusion

The source code confirms:

1. **fx, fy, fz are total forces on the surface element** — NOT force per unit area or force per unit length
2. **The norm keyword does NOT affect force output** — it only affects flux quantities
3. **The axisymmetric boundary (`ao`) affects normflux** (used for flux quantities) but does NOT automatically apply axisymmetric weighting to forces
4. **To get 3D axisymmetric force from 2D simulation**, you must manually multiply each element's force by 2πy_centroid
